# Supabase Schema — Design

- **Date:** 2026-10-11
- **Status:** Draft — awaiting review
- **Branch:** `develop`

## Goal

Turn the [data model draft](../../supabase/data-model.md) into a working local Supabase database:
- tables, row level security (RLS) and grants;
- quote numbering;
- the database functions behind the web app's actions and the slicer-worker's job handling;
- the slicing queue, storage buckets and the daily expiry job.

All of it is covered by pgTAP tests and runs on the local stack only.

## Decisions

| Concern | Choice |
|---|---|
| Environment | Local Supabase stack only. No cloud project is linked or pushed to. |
| CLI | Supabase CLI upgraded to the latest 2.x via `scoop update supabase` |
| Schema workflow | Declarative files in `supabase/schemas/`, plus one hand-written migration for what `supabase db diff` can't capture (see [Migrations](#migrations)) |
| Tests | pgTAP via `supabase test db`, files in `supabase/tests/database/` |
| Pricing | A later Edge Function. This schema stores the breakdown, which only the service role can write. |
| First owner | Local: `supabase/seed.sql`. Cloud (later): invite yourself, then a one-off `insert into staff` — documented, not automated. |
| Privileged functions | Thin `security invoker` wrappers in `public`, each calling a `security definer` function in the non-exposed `private` schema |

`.gitkeep` stays.

## Configuration (`config.toml`)

- `[db.migrations] schema_paths` lists the `schemas/` files in the order above.
- `[auth] enable_signup = false`, `site_url = "http://localhost:5173"`, and
  `additional_redirect_urls = ["http://localhost:5173/account"]`.
- `[storage] file_size_limit = "100MiB"`, so the `models` bucket limit can apply locally.
- `[api] schemas` keeps the defaults (`public`, `graphql_public`). `private` and `pgmq` are never exposed.

## Tables

As in the data model draft, with these changes and additions:

| Table | Change |
|---|---|
| all | `id bigint generated always as identity`; `created_at` / `updated_at` maintained by `private.set_updated_at()` |
| `quote_items` | Defaults `quantity 1`, `layer_height_mm 0.20`, `infill_percent 20`, `supports false` (functional analysis §3.4) |
| `quote_items` | `printer_id` and `material_id` are `on delete restrict` |
| `quote_items` | `item_total` is `generated always as (coalesce(override_total, computed_total)) stored` |
| `quote_items` | Check: `override_total` is null, or it is `>= 0` and `override_reason` is not blank |
| `quotes` | `valid_until date not null`. Filled at insert from `settings.default_validity_days` when not given. |
| `quotes` | `created_by` defaults to `auth.uid()` |
| `settings` | `energy_price_kwh` default `0`, so the migration can insert the single row |
| `private.quote_counters` | New: `year smallint primary key, last_seq integer not null`. Not exposed through the API. |

### Behaviour

**Shop date.** `private.shop_today()` returns today's date in `Europe/Rome`. The quote number year, the send check
and the expiry job all use it. This is the one place to change the timezone.

**Quote numbers.** A `before insert` trigger on `quotes` runs a `security definer` function. It:
1. bumps `private.quote_counters` with one upsert per insert:
   `insert … on conflict (year) do update set last_seq = last_seq + 1 returning last_seq`;
2. sets `number_year` and `number_seq`;
3. sets `number` to `<settings.quote_prefix>-<year>-<seq>`, with `seq` zero-padded to 4 digits and growing past 9999
   without being cut off.

Values for these columns supplied by the client are ignored.

**Draft-only editing.** Two `before update` triggers apply to every role, the service role included. A third
`before update or delete` trigger covers item deletes.
- `quotes`: when `old.status <> 'draft'`, the only allowed change is `status` moving from `sent` to `accepted`,
  `rejected` or `expired`. `updated_at` may change with it. Anything else raises.
- `quote_items`: an update raises unless the parent quote is `draft`. This freezes sent prices for good.
- `quote_items`: a delete raises unless the parent quote is `draft`. The exception is a cascade from deleting the
  quote, which itself is only allowed while it's a draft.

**Status changes and costs.** Status changes only through the functions below. Price and result columns are
written only through the functions below and by the service role.

**Repricing on quantity change.** When `quantity` changes, a `before update` trigger on `quote_items` clears the price
breakdown:
- clears `material_cost` … `markup_amount`, `markup_pct`, `computed_total` and `priced_at`;
- keeps `override_total` and `override_reason`.

The pricing Edge Function fills the breakdown in again later.

**Staff guard.** A `before update or delete` trigger on `staff`:
- only an owner may change `role` or `active`;
- raises if the change would leave zero active owners.

This covers the demotion, deactivation and deletion paths.

## Access

### Helpers
- `private.is_staff()` is true when the caller has a `staff` row with `active = true`.
- `private.is_owner()` additionally requires `role = 'owner'`.
- Both are `security definer` and `stable`, with `set search_path = ''`.
- Policies call them as `(select private.is_staff())`.

### Grants

Grants live in the hand-written migration. Since the 2026 Data API change, every grant to `anon` and
`authenticated` is explicit.

**Tables:**
- `anon` gets nothing.
- `revoke all on all tables in schema public from anon, authenticated` runs first.
- `authenticated` then gets `select` on all public tables, plus these writes. `service_role` gets `all` on all public tables
explicitly too, rather than relying on default privileges.

| Table | insert | update | delete |
|---|---|---|---|
| `staff` | ✓ | `display_name`, `language`, `role`, `active` | — |
| `printers`, `materials` | ✓ | ✓ | ✓ |
| `settings` | — | every column except `id` | — |
| `clients` | ✓ | ✓ | ✓ |
| `quotes` | `client_id`, `valid_until`, `notes` | `client_id`, `valid_until`, `notes` | ✓ |
| `quote_items` | — (created by function) | `description`, `quantity` | ✓ |
| `slicing_jobs` | — | — | — |

**Schemas and functions:**
- `grant usage on schema private to authenticated, service_role`.
- `execute` on every function in `public` and `private` is revoked from `public` and `anon`.
- Web app functions are granted to `authenticated`, and worker functions to `service_role`.

### RLS policies

Every policy is `to authenticated`. UPDATE policies have both `using` and `with check`.

| Table | select | insert | update | delete |
|---|---|---|---|---|
| `staff` | staff | owner | owner, or the row's own user | — |
| `printers`, `materials`, `settings` | staff | owner | owner | owner |
| `clients` | staff | staff | staff | owner |
| `quotes` | staff | staff | staff, while `status = 'draft'` | owner, while `status = 'draft'` |
| `quote_items` | staff | — | staff, parent quote draft | staff, parent quote draft |
| `slicing_jobs` | staff | — | — | — |
| `private.quote_counters` | RLS enabled, no policies; only reached through the `security definer` trigger | | | |

### Functions

Each function in `public` is a `security invoker` SQL wrapper. It calls the same-named `security definer` function in
`private`, which:
- has `set search_path = ''`;
- checks `private.is_staff()` or `private.is_owner()` first;
- raises with a stable error code in the message, for example `quote_not_draft`.

**Web app functions:**

| Function | Who | Does |
|---|---|---|
| `create_quote_item(quote_id, model_path, original_filename, description, printer_id?, material_id?, quantity?, layer_height_mm?, infill_percent?, supports?) → bigint` | staff | See the checks and steps below. Returns the item id. |
| `update_quote_item_settings(item_id, printer_id, material_id, layer_height_mm, infill_percent, supports) → void` | staff | Replaces all slicing inputs. If any differ: clears results and price breakdown (override kept) and enqueues a job if printer and material are set. No change → no job. A printer or material that changes must be active; an unchanged inactive one is kept. |
| `retry_slicing(item_id) → bigint` | staff | Draft quote, item's latest job `failed` → enqueues a new job, returns its id |
| `set_markup_override(quote_id, pct numeric or null) → void` | owner | Draft only. `pct >= 0` or null. Clears every item's price breakdown. |
| `set_price_override(item_id, total, reason) → void` | owner | Draft only. `total >= 0`, reason not blank. |
| `clear_price_override(item_id) → void` | owner | Draft only |
| `get_quote_send_blockers(quote_id) → table(quote_item_id bigint, code text)` | staff | Empty means the quote can be sent. Codes are listed below. |
| `mark_quote_sent(quote_id) → void` | staff | Raises `quote_not_sendable` if there are any blockers. Otherwise sets `sent` and `sent_at = now()`. |
| `mark_quote_accepted(quote_id)`, `mark_quote_rejected(quote_id) → void` | staff | `sent` quotes only |

`create_quote_item` checks:
- the quote is a draft;
- `model_path` starts with `<quote_id>/`;
- an object exists at that path in the `models` bucket;
- the chosen printer and material are active.

It then:
1. inserts the item;
2. if both printer and material are set, enqueues a job.

**Enqueue a job** (shared by the functions above) runs in the caller's transaction:
1. insert a `slicing_jobs` row with status `queued`;
2. `pgmq.send('slicing_jobs', <message>)`, with the message shaped as in
   [slicer-worker → Job message](../../services/slicer-worker.md#job-message-proposed).

**Send blockers:**

| Code | When |
|---|---|
| `not_draft` | Quote is not `draft` (no item id) |
| `no_items` | Quote has no items (no item id) |
| `valid_until_past` | `valid_until < private.shop_today()` (no item id) |
| `missing_printer_or_material` | Item has no printer or no material |
| `not_sliced` | Item's latest job is not `succeeded`, or the item has no results |
| `not_priced` | `item_total` is null |
| `does_not_fit` | Any bbox axis exceeds the printer's build volume on the same axis |

**Worker functions:**

All are executable by `service_role` only and change the job, the item and the queue message in one transaction.
They replace steps 1, 2, 6 and 7 of the worker's processing loop.

| Function | Does |
|---|---|
| `worker_claim_job(visibility_timeout_s int, max_attempts int) → table(msg_id bigint, read_ct int, message jsonb)` | `pgmq.read` of one message. If `read_ct > max_attempts`: marks the job `failed` ("worker stopped on every attempt"), archives the message and reads again. Otherwise marks the job `running` with `started_at` and `attempts = read_ct`, and returns the message. Returns no rows when the queue is empty. |
| `worker_complete_job(msg_id bigint, job_id bigint, results jsonb) → void` | Writes the results on the job, marks it `succeeded` with `finished_at`, and deletes the message. If this job is the item's newest job, copies `print_time_s`, `filament_g` and the bbox onto the item. An older job never overwrites a newer one. |
| `worker_fail_job(msg_id bigint, job_id bigint, error text, final boolean) → void` | Records `error`. If `final`: marks the job `failed` with `finished_at` and archives the message. Otherwise sets it back to `queued` and leaves the message for redelivery. |

A job whose item was deleted (cascade) is gone. In that case the claim and complete functions archive the message and
return nothing.

## Migrations

`supabase db diff` with declarative schemas does not capture:
- data changes (DML);
- column and schema privileges;
- `alter policy`;
- comments.

So `<ts>_grants_and_setup.sql` is written by hand with `supabase migration new grants_and_setup` and contains:

1. The grants and revokes from [Access](#grants).
2. `insert into public.settings (id) values (1)`.
3. `select pgmq.create('slicing_jobs')`.
4. The storage buckets:
   - `models`: private, 100 MB limit, no MIME restriction, since browsers report STL and 3MF types inconsistently;
   - `branding`: private, 1 MB limit, `image/png`, `image/jpeg` and `image/svg+xml`.
5. Storage policies on `storage.objects`, all `to authenticated`:
   - `models`:
     - staff can `select`, `update` and `delete`;
     - staff can `insert` only when the first path folder is the id of a `draft` quote;
   - `branding`:
     - staff can `select`;
     - owners can `insert`, `update` and `delete`.
6. `cron.schedule('expire-quotes', '15 0 * * *', 'select private.expire_quotes()')`. The job runs at 00:15 UTC.
   `private.expire_quotes()` lives in the declarative files. It sets `status = 'expired'` on `sent` quotes where
   `valid_until < private.shop_today()`.

The generated `initial_schema` migration is reviewed for duplicate grants coming from default privileges before it
is committed.

## Seed (`supabase/seed.sql`)

- **Two Auth users,** each with an identity and a `staff` row:
  - `owner@3dquote.local` (owner);
  - `operator@3dquote.local` (operator).

  Both use password `password123`. That is fine for the local stack only, and getting-started says so.
- **Settings:** the shop name and an energy price.
- **Sample data:**
  - two printers;
  - three materials;
  - one client.

## Tests (pgTAP)

Each file runs in a transaction that is rolled back. Fixtures create their own users and staff rows. Role switching
uses `set local role` plus `set_config('request.jwt.claims', …)`.

| File | Covers |
|---|---|
| `01_structure.test.sql` | Tables exist, RLS is enabled on every public table, every FK column is indexed |
| `02_grants.test.sql` | `anon` can't read any public table or execute any function in `public` or `private`. `authenticated` can't update `status`, price or result columns. Worker functions can't be executed by `authenticated`. |
| `03_rls.test.sql` | Each role sees and writes what the policy table says: anon, a logged-in user without a staff row, an inactive staff member, an operator, an owner. |
| `04_staff.test.sql` | An operator can change their own name and language but not their role. The last active owner can't be demoted, deactivated or deleted. |
| `05_numbering.test.sql` | Sequential numbers, prefix from settings, restart in a new year, padding past 9999, client-supplied values ignored |
| `06_quote_items.test.sql` | `create_quote_item` writes the item, the job and the queue message together. It rejects a wrong path prefix, a missing object, a non-draft quote and an inactive printer. Settings changes clear results and enqueue; an unchanged call doesn't. Quantity change clears the price and keeps the override. Retry works only after a failure. |
| `07_lifecycle.test.sql` | Each send blocker is reported. `mark_quote_sent` sets `sent_at`. Items and quotes of a sent quote are frozen for the service role too. Accept and reject only work from `sent`. `expire_quotes` moves only past-due sent quotes. |
| `08_overrides.test.sql` | Price and markup overrides are owner only and draft only, and reason is required |
| `09_worker.test.sql` | Claim marks the job running. Claim with `read_ct` over max fails and archives it. Complete copies results onto the item only for the newest job. Fail with `final` false re-queues, with `final` true fails and archives. |
| `10_storage.test.sql` | Bucket policies: operators can't write `branding`, and uploads to `models` need a draft quote's folder |

**Done** means:
- `supabase db reset` applies migrations and seed cleanly;
- `supabase test db` passes;
- `supabase db advisors` reports no security or performance findings, or each remaining one is explained in ADR-0003;
- `supabase db diff` against the schema files is empty;
- the existing `npm test`, `npm run lint` and `npm run build` still pass.
