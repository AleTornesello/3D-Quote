# Web app — developer guide

- **Location:** `apps/web/` (npm workspace `@3d-quote/web`)
- **What it does:** see the [functional analysis](functional-analysis.md). Why the stack is what it is:
  [ADR-0002](../architecture/adr/0002-frontend-stack.md).

## Running

1. Create `apps/web/.env.local` from `apps/web/.env.example` and fill in the Supabase project URL and publishable
   key (Supabase dashboard → Project Settings → API). `.env.local` is git-ignored.
2. From the repository root:

| Command | What it does |
|---|---|
| `npm run dev` | Dev server (extra args reach Vite: `npm run dev -- --port 5199`) |
| `npm run build` | Type-check (`tsc -b`) and production build into `apps/web/dist/` |
| `npm test` | Vitest, once (`npm run test:watch --workspace @3d-quote/web` for watch mode) |
| `npm run lint` | ESLint |
| `npm run format` / `npm run format:check` | Prettier write / check |
| `npm run gen:types` | Regenerate `apps/web/src/lib/database.types.ts` from the local database (`supabase start` must be running) |
| `npm run check:types-fresh` | Fail if the committed types differ from the local database; run after schema changes |

Without the env variables the app shows a "Supabase is not configured" screen listing what's missing.

## Structure

```
apps/web/src/
├── main.tsx          # initialises i18n, reads env, renders <App>
├── index.css         # Tailwind + shadcn theme tokens
├── app/              # App, AppProviders, routes (SECTION_PAGES), sections
├── lib/              # env, typed Supabase client, generated database types, query client, formatting, form helpers
├── data/             # one TanStack Query module per entity (quotes and quote items included), AppError mapping,
│                     # query keys, Edge Function calls, the model uploader, quote rules and live updates
├── i18n/             # i18next setup, language detection/switching, locales/it.json + en.json
├── auth/             # session (AuthProvider, RequireAuth), staff profile (StaffProvider, useStaff), RequireOwner
├── layout/           # AppShell (sidebar / drawer), Navigation, LanguageSwitcher
├── pages/            # one component per page, plus a folder per page for its form and sheet
├── components/       # shared building blocks (DataTable, FormField, FormSheet, dialogs, leave guard)
├── components/ui/    # shadcn components (owned code, generated by the shadcn CLI)
└── test/             # setup, fake Supabase client with an in-memory query builder, fixtures, renderApp
```

## Conventions

- **Pages** live in `src/pages/`, one component per file, named `XxxPage`.
- **Text:** every user-visible string goes through `t()`. Add each key to **both** `src/i18n/locales/it.json` and
  `en.json` — a test fails if the two catalogs differ. Format numbers, dates and money with `Intl` using the active
  language.
- **Data** goes through `src/data/`: one module per entity exporting TanStack Query hooks (`usePrinters`,
  `useSavePrinter`, …). Pages never call Supabase directly. Hooks reach Supabase only through `useSupabase()`, which
  returns a client typed from `src/lib/database.types.ts`. Regenerate the types with `npm run gen:types` after every
  schema change.
- **Errors:** hooks throw `AppError` (`src/data/errors.ts`), which maps Postgres/PostgREST codes to a `kind` and an
  i18n `messageKey`. A duplicate also names the field. Saves end in `.select().single()` and deletes in `.select('id')`,
  so a write that RLS silently filters out becomes `notFound` instead of looking like success. When a background
  refetch fails, `DataTable` keeps the cached rows and shows the error with Retry above them; `StaffProvider` shows
  its full-page error only when no profile has loaded yet.
- **Roles:** `useStaff()` gives `{ userId, displayName, role, isOwner, language }`. Hide owner-only actions; don't
  disable them. Wrap owner-only pages in `<RequireOwner>`. The database (RLS) is the authority.
- **Forms:** react-hook-form + zod. Numbers are text fields checked by `numberField()`, which accepts `0,40` and `0.40`
  with the same limits as the database. Messages are i18n keys shown by `FormField`. Create/edit forms open in a
  `FormSheet`; full-page forms call `useLeaveGuard(isDirty)`.
- **Formatting:** `useFormat()` for numbers, money (the shop currency) and dates in the UI language.
- **UI components:** add them with the shadcn CLI installed in the workspace (not `@latest`), never by hand:

  ```bash
  npx shadcn add <component> -c apps/web
  ```

  It overwrites `button.tsx` and `label.tsx` when they are dependencies. Restore them with
  `git checkout -- apps/web/src/components/ui/button.tsx apps/web/src/components/ui/label.tsx`, because they carry the
  `pointer-coarse` touch-target sizes. Run `npm run format` afterwards.
- **Tests** sit next to the code as `*.test.ts(x)` and query by role and visible (Italian) text. `src/test/setup.ts`
  stubs what jsdom lacks (`ResizeObserver`, `matchMedia`, `scrollIntoView`, `setPointerCapture`). Vitest's
  `testTimeout` is 15000 ms and Testing Library's `asyncUtilTimeout` 3000 ms, so multi-step page tests don't time out
  on a loaded machine.
  `renderApp(path, { session, staff, tables, rpc, functions })` renders the real routes against a fake Supabase client:
  - `staff` is the signed-in user's staff row (default: an owner; `null` means no access);
  - `tables` seeds in-memory rows;
  - `rpc` maps database function names to handlers; `functions` does the same for Edge Functions.

  It returns `{ db, user, auth, router, queryClient, uploader, realtime }`:
  - `db.calls('printers')` lists the requests made (`{ op, values, filters }`);
  - `db.failNext('printers', { code, message })` makes the next one fail;
  - fixtures live in `src/test/fixtures.ts`.
- **Style** is enforced by Prettier (no semicolons, single quotes, width 100) and ESLint (including `jsx-a11y`).

## Quotes

- **List:** `QuotesPage` reads the `quotes_list` view. Search, filters, sort and page live in the URL
  (`parseQuoteListParams` / `toQuoteListSearch` in `src/data/quote-rules.ts`). `/quotes/new` is the same page with
  the New quote sheet open; the sheet stays open with a loading state (and Retry on error) while settings and the
  client load.
- **Editor:** `QuoteEditorPage` with its parts in `src/pages/quote-editor/`. Item changes save as soon as they happen
  (selects and switches at once, text and numbers on blur or Enter, through `InlineField`). The item card disables
  every control while any of its saves is pending. Download opens the tab synchronously in the click, then points it
  at the signed URL (so Safari doesn't block it).
- **Uploads:** `useModelUploader()` (`src/data/model-upload.ts`) uploads with `tus-js-client` to
  `/storage/v1/upload/resumable` in 6 MB chunks; `useUploads` runs at most three at a time and keeps files in memory
  for Retry. Leaving the editor asks first and cancels running and waiting uploads; closing or reloading the tab
  while uploads run brings up the browser's own warning (`beforeunload`). A quote that leaves draft (an upload
  refused for that reason, or a refetch showing the new status) cancels every pending upload. Tests get a
  `FakeUploader` (`renderApp(...).uploader`) and finish, fail or advance each upload by hand.
- **Live status:** `useQuoteLiveUpdates` subscribes to `quote_items` and `slicing_jobs` (Supabase Realtime) and
  refetches the items on any change. The channel is rebuilt whenever the item ids change, so every subscription
  after the editor's first one refetches too (as does a reconnect). Tests drive it with `renderApp(...).realtime`
  (`emit`, `reconnect`, and `hold` / `release` to keep new subscriptions pending); a channel only receives changes
  once subscribed.
- **Pricing:** `useAutoPrice` calls the `price-quote` Edge Function whenever a draft has items with results and no
  price; it retries once per pending item, then shows "Price not calculated" until the item changes. Recalculate and
  the error toast's Retry always call. Edge Functions are called through `invokeFunction`
  (`src/data/edge-functions.ts`); tests pass handlers with `renderApp(path, { functions })`. `price-quote`
  defaults to a handler that prices nothing, so tests with sliced-but-unpriced items don't raise error toasts.
- **PDF:** `ExportPdfDialog` (`src/pdf/`) builds a `QuotePdfData` with `toQuotePdfData` (pure: translated and
  formatted in the chosen language, VAT included), renders it with `QuotePdf` (`@react-pdf/renderer`) and downloads
  it. The renderer is a context (`usePdfRenderer`) whose real implementation lazy-loads react-pdf, so the library is a
  separate chunk fetched on the first export. Tests get a `FakePdfRenderer` (`renderApp(...).pdf`, with `rendered` and
  `failWith`); `QuotePdf.render.test.ts` renders the real thing in a Node environment and reads the text back with
  `pdfjs-dist`. The PDF uses the built-in Helvetica: Western European letters and € print correctly, other scripts
  (Cyrillic, Greek…) don't until a font is embedded.
- **VAT:** `settings.vat_rate_pct` is the shop rate; `mark_quote_sent` copies it onto the quote. `vatRateFor` and
  `quoteTotals` (`src/data/quote-rules.ts`) work in integer cents; the editor's totals and the PDF use them.
- **Test fake:** `FakeDb#configure({ defaults, embeds, writable })` adds what the database would: `renderApp` fills
  a new quote's defaults and embeds its `client` and `creator`, gives items an empty `job` unless seeded, and lets
  updates and deletes reach draft quotes only (the RLS policy). A `range` starting past the last row fails with
  `PGRST103`, like PostgREST; one starting right at the end returns no rows.

### Simulating a slice locally

The slicer worker doesn't exist yet. With the local stack running, slice the oldest queued job by hand in Studio's
SQL editor (`http://127.0.0.1:54323`), which runs as `postgres`:

```sql
select msg_id, message->>'job_id' as job_id from public.worker_claim_job(300, 3);
-- then, with the two values it returned:
select public.worker_complete_job(
  <msg_id>, <job_id>,
  '{"print_time_s": 19800, "filament_g": 120.5, "filament_mm": 40000, "layer_count": 266,
    "bbox_x_mm": 100, "bbox_y_mm": 80, "bbox_z_mm": 40, "slicer_version": "manual"}'::jsonb
);
```

An open editor shows the results without reloading, then prices the item.

## Adding a section page

1. Create `src/pages/<Name>Page.tsx`.
2. If it's a sidebar section, add it to `SECTIONS` in `src/app/sections.ts` with a `nav.*` label key and a
   `lucide-react` icon; add the key to both catalogs.
3. In `src/app/routes.tsx`, add the page to `SECTION_PAGES` (wrap it in `<RequireOwner>` if it is owner-only, and
   set `ownerOnly: true` in `SECTIONS`).
4. Add a test using `renderApp`.

## Not done yet

- **Orphaned model files** — files whose item was never created or whose removal failed stay in `models` until a
  cleanup job exists.
- **Inviting, removing and deactivating staff** — needs an Edge Function; until then use the Supabase dashboard.
- **Redirect URLs** — the reset email links to `<origin>/account?reset=1`. Allow it under Supabase → Authentication →
  URL Configuration → **Redirect URLs** for every environment (for example `https://<host>/account**`), or Supabase
  falls back to the Site URL.
- **Bundle size** — the main JS chunk is ~1.1 MB (1,125 kB, ~331 kB gzip); split routes with lazy loading (the PDF
  library is already its own lazy chunk, ~1,202 kB).
- **End-to-end tests** (Playwright).
